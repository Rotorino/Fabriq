# Руководство пользователя: Симулятор производственной линии Fabriq

Fabriq — это модульный инструмент для дискретно-событийного моделирования, предназначенный для анализа и оптимизации производственных процессов. Это руководство содержит пошаговые инструкции по использованию ПО.

## 1. Установка

### Требования
- Python 3.10 или выше
- `pip` (менеджер пакетов Python)

### Шаги
1. Перейдите в корневую директорию проекта.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

---

## 2. CLI

CLI идеально подходит для пакетной обработки или запуска симуляций без графического интерфейса.

### Базовая команда
```bash
python -m app.main --config configs/base_scenario.json
```

### Параметры
- `--config [ПУТИ...]`: Один или несколько путей к файлам JSON/YAML.
- `--results-dir DIR`: Директория для сохранения отчетов (по умолчанию: `results`).
- `--seed INT`: Переопределение random seed для воспроизводимости.

## 3. Веб-интерфейс

Интерактивный дашборд для запуска симуляций и визуализации данных.

### Запуск
```bash
streamlit run app/ui.py
```

### Основные разделы
1. **Главная**: Обзор системы и быстрый старт.
2. **Запуск симуляции**: 
   - **Выбор сценария**: Доступно 15 предустановленных вариантов (Узкие места, Стресс-тесты и др.).
   - **Схема линии**: Живая визуализация этапов (напр., "Цех сборки", "Контроль качества").
   - **Параметры**: Настройка количества партий и вероятности поломок ползунками.
   - **Редактор JSON**: Прямое редактирование структуры сценария в браузере.
3. **Результаты**:
   - **Сводка**: Ключевые метрики (КПД, процент брака).
   - **Графики**: Интерактивные чарты длин очередей и загрузки станков.
   - **История**: Сравнение текущего запуска с предыдущими в рамках сессии.

## 4. Настройка сценариев

Сценарии описываются в JSON-файлах. Теперь они используют понятные "человеческие" названия.

- `stages`: Список этапов производства.
  - `name`: Понятное название (напр., "Участок лазерной резки").
  - `machines`: Станки на этом этапе.
    - `name`: Название станка (напр., "Станок ЧПУ №1").
    - `processing_time`: Время обработки одной партии.
    - `breakdown_probability`: Вероятность поломки (0.0 - 1.0).

---

## 5. Интерпретация результатов

- **Загрузка (Utilization)**: % времени, когда станок был занят. Оптимально >80%.
- **Процент брака (Rejection Rate)**: % партий, сброшенных из-за переполнения буферов. Сигнализирует об "узком месте".
- **Длина очереди**: Если она постоянно растет — этап не справляется с нагрузкой.
