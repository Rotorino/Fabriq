# Результат симуляции

Метод `SimulationEngine.run()` возвращает `SimulationResult`.
Перед запуском ядро копирует входные партии и производственную линию, поэтому
исходные объекты сценария не накапливают состояние после симуляции. Все
измененные статусы, очереди, буферы и состояния станков нужно брать из
`SimulationResult`, а не из объектов, переданных в `SimulationEngine`.

```python
@dataclass(slots=True)
class SimulationResult:
    events: list[EventLogRecord]
    batches: list[Any]
    stages: list[Any]
    machines: list[Any]
    simulation_time: float
    scenario_name: str
    raw_data: dict[str, Any]
```

## `events`

Список записей журнала. Каждая запись описывает обработанное событие:

```python
@dataclass(slots=True)
class EventLogRecord:
    timestamp: float
    event_type: str
    batch_id: str | None
    stage_id: str | None
    machine_id: str | None
    result: str
    details: dict[str, Any]
```

Журнал предназначен для модуля аналитики. По нему можно восстановить:

- когда партия вошла в очередь;
- когда началась обработка;
- когда закончилась обработка;
- когда партия перешла на следующий этап;
- когда произошла поломка;
- когда закончился ремонт;
- когда партия была забракована;
- когда симуляция была остановлена.

## `batches`

Итоговые объекты партий после симуляции. Партии могут иметь статусы:

- `completed`;
- `rejected`;
- `waiting`;
- `processing`.

`waiting` и `processing` после завершения симуляции означают, что партия не успела завершить маршрут в пределах `simulation_duration`.

Это копии входных партий со всеми изменениями состояния. Исходный список
партий остается пригодным для повторного запуска той же конфигурации.

## `stages`

Итоговые этапы производственной линии. Если объект этапа имеет поле `queue`, оно содержит актуальное состояние очереди на момент завершения симуляции.

Это копии входных этапов. Рабочие очереди и буферы в исходном объекте
`ProductionLine` не изменяются.

## `machines`

Итоговые станки. Для каждого станка сохраняются:

- статус;
- `busy_until`;
- текущая партия, если поле поддерживается объектом станка;
- прерванная партия, если станок сломан и поле поддерживается объектом станка.

## `raw_data`

Технические данные для аналитики:

- `queue_lengths` - наблюдения длины очереди по времени;
- `machine_activity` - изменения состояния станков.
- `buffer_lengths` - наблюдения длины буферов по времени.

Внутренние ключи, начинающиеся с `_`, не попадают в публичный `raw_data` результата.
