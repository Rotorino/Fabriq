# Fabriq

Fabriq - модульное Python-приложение для дискретно-событийного моделирования производственных процессов. Проект включает загрузку JSON/YAML-конфигураций, сборку производственной линии, генерацию партий, симуляцию, расчет метрик, экспорт отчетов, сравнение сценариев и построение SVG-графиков.

Полный запуск:

```bash
python -m app.main --config configs/base_scenario.json
```

Сравнение обязательных сценариев:

```bash
python -m app.main --config \
  configs/base_scenario.json \
  configs/high_load.json \
  configs/frequent_breakdowns.json
```

Ниже описаны ключевые модули системы. Отдельно документированы:

- ядро моделирования `engine`;
- модуль описания линии и сценариев `domain + scenario`;
- контракт интеграции между модулями;
- результат симуляции;
- проверка и запуск полного приложения.

# Состав системы

```text
app/            CLI-точка входа
domain/         общие сущности, enum и DTO
scenario/       загрузка, валидация и сборка сценариев
engine/         дискретно-событийное ядро
analytics/      расчет метрик
reporting/      экспорт JSON, CSV и TXT
visualization/  построение графиков
configs/        входные сценарии
tests/          unit- и интеграционные тесты
```

# Ядро моделирования Fabriq

Ядро моделирования отвечает за дискретно-событийную симуляцию производственной линии. Оно не загружает конфигурации, не строит графики и не считает итоговые бизнес-метрики. Его задача - принять готовую модель линии, принять партии, обработать события во времени и вернуть технический результат для аналитики и отчетности.

Текущая реализация находится в пакете `engine`:

```text
engine/
├── context.py
├── dispatcher.py
├── event_queue.py
├── events.py
├── handlers.py
└── simulator.py
```

## Зона ответственности ядра

Ядро выполняет следующие задачи:

- создает начальные события прибытия партий;
- хранит события в стабильной приоритетной очереди;
- обрабатывает события в порядке времени;
- меняет состояния партий и станков;
- учитывает очередь этапа и занятость станков;
- моделирует завершение обработки, переход на следующий этап, поломку, ремонт и брак;
- защищает цикл симуляции от бесконечной серии событий без продвижения времени;
- формирует журнал обработанных событий;
- возвращает итоговые состояния партий, этапов и станков.

## Что не входит в ядро

В ядро намеренно не входят:

- загрузка JSON/YAML-конфигураций;
- валидация производственной линии;
- генерация сценариев и партий;
- расчет итоговых бизнес-метрик;
- экспорт CSV/JSON/TXT-отчетов;
- визуализация.

Эти задачи относятся к модулям `scenario`, `analytics`, `reporting` и `visualization`.

## Модуль сценариев

Модуль сценариев отвечает за то, чтобы ядро никогда не работало с сырой конфигурацией напрямую. Он:

- загружает `JSON` и `YAML`;
- валидирует структуру линии;
- валидирует связи между этапами;
- проверяет вероятности, времена и идентификаторы;
- генерирует партии несколькими способами;
- возвращает `ScenarioInput` с `ProductionLine`, `Batch` и `ScenarioConfig`.

Подробное описание вынесено в раздел "Модуль сценариев".

## Минимальный пример запуска

```python
from engine import SimulationEngine
from scenario import build_scenario, load_config

scenario_input = build_scenario(load_config("configs/base_scenario.json"))

result = SimulationEngine(
    production_line=scenario_input.production_line,
    batches=scenario_input.batches,
    simulation_duration=scenario_input.scenario_config.simulation_duration,
    scenario_name=scenario_input.scenario_config.name,
).run()

print(result.events)
print(result.event_log)
print(result.batches)
print(result.machines)
```

`production_line` и `batches` подготавливаются модулем сценариев. Ядро ожидает, что эти объекты имеют поля, описанные в разделе "Контракт интеграции".

`result.events` содержит сырые обработанные `Event`, а `result.event_log` - журнал результатов обработки, пригодный для аналитики и отчетности.
