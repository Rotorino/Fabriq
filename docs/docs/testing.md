# Проверка и тесты

Тесты разделены по зонам ответственности:

- `tests/test_engine.py` - ядро моделирования;
- `tests/test_scenario.py` - модуль сценариев и предметная модель;
- `tests/test_analytics.py` - аналитика и сравнение сценариев;
- `tests/test_reporting.py` - экспорт и comparison-report;
- `tests/test_integration.py` - полный сквозной pipeline.

Запуск:

```bash
python -m unittest discover -s tests -q
```

Дополнительная проверка синтаксиса:

```bash
python -m compileall app domain scenario engine analytics reporting visualization tests
```

Pytest-проверка:

```bash
python -m pytest -q
```

Если `pytest` не установлен в окружении, базовой проверкой остается `unittest`.

Проверка полного запуска:

```bash
python -m app.main --config configs/base_scenario.json
python -m app.main --config configs/high_load.json
python -m app.main --config configs/frequent_breakdowns.json
python -m app.main --config configs/base_scenario.json configs/high_load.json configs/frequent_breakdowns.json
```

## GitHub Actions

Workflow `.github/workflows/ci.yml` запускается на push и pull request для веток `Dev`, `develop`, `main` и `master`. Он рассчитан на расширение проекта:

- ставит зависимости из `requirements.txt`;
- компилирует найденные Python-пакеты и `tests`;
- запускает универсальный `unittest discover`;
- запускает `pytest`;
- прогоняет все сценарии из `configs/*.json` через CLI;
- проверяет повторяемость ядра с фиксированным seed;
- сохраняет `logs/` и `results/` как артефакты workflow.

## Что покрывают тесты

Текущие тесты проверяют:

- загрузку валидного JSON-конфига;
- загрузку YAML-конфига при наличии `PyYAML`;
- ошибку при несуществующем этапе;
- ошибку при неверной вероятности;
- ошибку при `seed=True`;
- генерацию партий с фиксированным `seed`;
- корректность построения `ProductionLine`;
- поддержку нескольких входных этапов при явном маршруте;
- корректность трех обязательных сценариев;
- порядок событий в `EventQueue`;
- стабильность сортировки событий с одинаковым временем;
- ошибку при извлечении события из пустой очереди;
- прохождение партии через несколько этапов;
- ожидание партии при занятом станке;
- корректную работу ограниченной очереди при зарезервированном старте обработки;
- отправку партии в буфер при заполненной очереди;
- выбраковку партии при заполненной очереди и заполненном или отключенном буфере;
- параллельный старт разных партий на разных станках;
- поломку станка, повторную постановку партии в очередь после ремонта и завершение прерванной обработки;
- отсутствие зависания при нулевой длительности обработки;
- выбраковку партии;
- обработку события завершения ровно на `simulation_duration`;
- повторный запуск одного и того же объекта сценария без накопления состояния во входных партиях, очередях и станках.
- расчет таблицы сравнения сценариев;
- экспорт comparison-report в JSON/CSV/TXT.

## Критерии готовности ядра

Ядро считается готовым к интеграции, если выполняются условия:

- события обрабатываются в правильном порядке;
- партия проходит через этапы корректно;
- при отсутствии свободного станка партия остается в очереди;
- при заполненной очереди партия отправляется в буфер или выбраковывается, если буфер недоступен;
- после завершения обработки партия переходит дальше по маршруту;
- поломка станка влияет на обработку и планирует ремонт;
- после ремонта прерванная партия возвращается в очередь и дорабатывает оставшееся время;
- симуляция завершается без зависаний;
- конфигурация с `processing_time=0` не вводит движок в бесконечный цикл;
- формируется журнал событий с временем, типом события, партией, этапом, станком и результатом;
- повторный запуск сценария возвращает результат по копиям входной модели и не портит исходные объекты.

## Критерии готовности модуля сценариев

Модуль сценариев считается готовым к интеграции, если выполняются условия:

- линию можно описать в конфиге;
- конфиг корректно читается из JSON;
- YAML-конфиг поддерживается при установленном `PyYAML`;
- ошибки конфигурации обнаруживаются до запуска симуляции;
- `seed` и `batches.seed` не принимают булевы значения;
- партии корректно генерируются в режимах `fixed`, `template`, `equal_intervals`, `random_intervals`;
- генерация повторяема при фиксированном `seed`;
- при нескольких входных этапах требуется явный маршрут партии;
- доступны три обязательных сценария;
- ядро получает валидные `ProductionLine`, `Batch` и `ScenarioConfig`.
